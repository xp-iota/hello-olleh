   ## Review

   Both changes are regressions. I'd block this PR.

   ### `total()` — off-by-one + out-of-bounds crash

   ```ts
   for (let i = 1; i <= items.length; i++) sum += items[i].price * items[i].qty
   ```

   Two bugs in one line:

   1. **Starts at `i = 1`** — `items[0]` is never counted, so the first item is silently dropped from the total.
   2. **Runs to `i <= items.length`** — the last iteration reads `items[items.length]`, which is `undefined`. `undefined.price` throws `TypeError`.

   Net effect: for any non-empty cart this function **throws**, so it's not even "wrong total", it's broken. It also produces a wrong result rather than failing loudly for an empty array? No — empty is the only case that works, returning `0`.

   ```ts
   for (let i = 0; i < items.length; i++) sum += items[i].price * items[i].qty
   ```

   Even fixed, the rewrite has no upside over the original `reduce` — it's just longer. Unless there's a measured perf reason, revert.

   ### `applyCoupon()` — `eval` on a lookup table

   ```ts
   return eval('COUPONS.' + code) ?? 0
   ```

   Three problems, in order of seriousness:

   1. **Code injection.** `eval` with a string built from `code` executes whatever is passed in. The `COUPONS.` prefix is not a sandbox: `code = "x; doEvil()"` parses as `COUPONS.x; doEvil()`. If `code` is ever user-supplied (it's a coupon field — it is), this is RCE. Fails `no-eval` lint rules too.
   2. **Changes behavior for non-identifier codes.** Coupon codes like `"SAVE-10"` become `COUPONS.SAVE-10`, i.e. `COUPONS.SAVE - 10` → `NaN` (not `0`), because `??` doesn't catch `NaN`. Bracket access handled these correctly; dotted access can't represent them at all.
   3. **Prototype access.** `COUPONS.constructor` / `__proto__` / `toString` return inherited values instead of `0`.

   Revert to:

   ```ts
   return COUPONS[code] ?? 0
   ```

   If you want to harden the original (the inherited-prop issue is real there too), use `Object.hasOwn(COUPONS, code)` or make `COUPONS` a `Map`.

   ### Suggested diff

   ```ts
   export function total(items: Item[]): number {
     return items.reduce((sum, it) => sum + it.price * it.qty, 0)
   }

   export function applyCoupon(code: string): number {
     return COUPONS[code] ?? 0
   }
   ```

   ### Also

   There are clearly no tests covering these two paths, or this wouldn't have landed. Worth adding cases for: empty cart, single item, unknown coupon, and hyphenated coupon code.

   Want me to apply the revert and add those tests?
