════════ M10.d · 专项真实演示：注入 SKILL.md 前后的真实作答对照（kind=model）════════
目标模型: anthropic-compat / MiniMax-M3 （真实 HTTP + SSE）

① A 组：不注入 skill
   这段改动有两个比较严重的问题，都**不建议合并**：

   ---

   ## 1. `total()`：循环边界错了 + 越界访问

   ```ts
   let sum = 0
   for (let i = 1; i <= items.length; i++) sum += items[i].price * items[i].qty
   ```

   - **起始索引错误**：数组下标从 `0` 开始，`i = 1` 会漏掉第一件商品。
   - **循环条件错误**：`i <= items.length` 会让最后一次循环访问 `items[items.length]`，即 `undefined`，运行时会抛 `TypeError: Cannot read properties of undefined`。
   - 即使修好边界，`for` + `items[i]` 比原来的 `reduce` 还要冗长，可读性没有提升。

   **建议：直接还原 `reduce` 版本。**

   ```ts
   return items.reduce((sum, it) => sum + it.price * it.qty, 0)
   ```

   如果只是为了规避 `reduce` 的一些争议风格，可以写成：

   ```ts
   let sum = 0
   for (const it of items) sum += it.price * it.qty
   return sum
   ```

   ---

   ## 2. `applyCoupon()`：引入了 `eval`，安全风险极高

   ```ts
   return eval('COUPONS.' + code) ?? 0
   ```

   - **任意代码执行**：`code` 来源不可控（用户输入？URL 参数？），攻击者传入 `code = "x; process.exit(1)"` 或 `code = "; require('fs').unlinkSync('/')"` 就能在服务器上执行任意 JS。
   - **作用域不可见**：`COUPONS` 是模块私有变量，字符串拼出来的 `'COUPONS.x'` 在 `eval` 里其实**也访问不到** `COUPONS`（`eval` 不会自动捕获外层局部变量，除非用间接 `eval` / `(0, eval)`），所以这个改动**功能上也是坏的**。
   - **绕过所有 lint/类型检查**。

   **建议：还原成 `COUPONS[code] ?? 0`，如果担心原型污染，可以加白名单：**

   ```ts
   export function applyCoupon(code: string): number {
     const allowed = ['SAVE10', 'FREESHIP'] as const
     if (!(allowed as readonly string[]).includes(code)) return 0
     return COUPONS[code] ?? 0
   }
   ```

   或者更通用一点：

   ```ts
   export function applyCoupon(code: string): number {
     if (!Object.prototype.hasOwnProperty.call(COUPONS, code)) return 0
     return COUPONS[code]
   }
   ```

   ---

   ## 总结

   | 改动 | 问题 | 建议 |
   |---|---|---|
   | `total` 改用 for 循环 | 下标越界 + 漏元素 | 回退 `reduce` 或用 `for...of` |
   | `applyCoupon` 用 `eval` | 安全漏洞 + 功能也是坏的 | 回退 `COUPONS[code] ?? 0`，必要时加白名单 |
