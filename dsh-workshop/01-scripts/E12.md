## 02. 五种派发与可逆生命周期

**旁白**

前半屏五段对照：广播、并行、串行、短路、接力，返回什么、按什么顺序跑都不一样。模式选错，控制流就变了——比如该短路的地方用了广播，第一个拒绝就不再有拦截效果。后半屏是生命周期：定时器、监听器都绑在纤程上，插件卸载时自动回收，挂起的等待被拒绝而不是永远悬着。最后两段是依赖状态机和同名服务隔离，解释了「依赖没齐就挂着、齐了才激活」这个行为。如果你只记一件事，就记住短路和广播那两段的差别：它决定你的安全检查有没有终止效果。

**运行命令**

```bash
cd dsh-example && npm run M12:real
```

## 03. 派发对了，生命周期能回收，上面才立得住

**旁白**

这一层不产生业务价值，但它决定别的层能不能安全组合。派发模式定义监听者如何叠加；纤程定义副作用何时回收。依赖没齐的时候纤程就挂着，齐了才激活——这解释了一个常见困惑：为什么少装一个依赖时，报错说的是「没有工厂」而不是「缺依赖」。知道这一点，排查装配问题会快很多。

## 04. 借语义，不搬架构

**旁白**

编排层跑 runner M12 --real。它借了几样东西：按相反顺序拆除、重复释放不出事、栈失效后再注册就报错、注册表删之前先比对身份、能力名字写错在类定义时就拒绝。这些都是装和拆两端的事。但它没有引入事件总线、代理式上下文和运行期热替换，因为它的图在启动时编译完就冻住了：运行中换实现会让同一次运行前后依赖不一致，指纹、恢复、审计全乱。借哪些不借哪些，是想清楚了才动手的。顺带说一句它为什么不做热替换：图在启动时编译完就冻住了，运行中换实现会让同一次运行前后依赖不一致，指纹、恢复和审计会同时失真。可逆性在这里是为装配失败回滚和测试隔离服务的。

**对照命令**

```bash
python -m runtime.runner M12 --real
```

## 05. 插件卸载了，定时器还在跑

**旁白**

最后说一个会拖垮长跑进程的问题：插件卸载了，定时器还在跑，进程也不肯退出。定位办法是看这些定时器是挂在插件自己的上下文上，还是直接用了全局定时器接口。修法是所有定时与监听都通过插件上下文注册，让它们随纤程一起回收。这一条也是整套课想留下的最后一个习惯：装上去的东西，得有人负责拆。

**症状**

卸载之后日志里还在冒出这个插件的输出，或者进程迟迟不退出。

**定位**

看这些定时器是挂在插件自己的上下文上，还是用了全局定时器接口。

**修改**

所有定时与监听都通过插件上下文注册，让它们随纤程一起回收。

## 06. 五种派发模式的调用差异摆在一起

**旁白**

代码在哪：M12 的 steps 里那个 dispatch modes 文件。五种模式并排放着，方便直接对照：返回值不同、执行顺序不同、有没有终止效果也不同。这一集的练习就是把短路改成广播，亲眼看到拦截失效。读完这一段，前面十一集里那些「为什么这个检查没生效」的问题，你基本都能自己回答了。整套课到这里就结束了，命令都还在，随时可以再跑。

## 07. 把一个短路派发改成广播，观察拦截行为变化

**旁白**

最后一个练习：把守卫用的短路监听改成广播，然后依次跑 M12 和 M01。可验证的答案是短路时第一个拒绝就终止，改成广播后后续监听器照样执行，拒绝不再具有终止效果。跑完这个练习，你就明白为什么派发模式不是风格选择——它直接决定你的安全检查有没有用。十二集到这里结束，仓库还在，命令随时可以再跑一遍。

**练习**

把守卫用的短路监听改成广播监听。

**验证命令**

```bash
cd dsh-example && npm run M12 && npm run M01
```

**可验证答案**

短路时第一个拒绝就终止；改成广播后后续监听器仍会执行，拒绝不再具有终止效果。
