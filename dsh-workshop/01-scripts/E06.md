# 第 6 集 · 人在环路（M06）

> 本集任务：让危险操作先回到人这里：工具在执行前请示，没有应答方就必须拒绝
> 运行命令：`cd dsh-example && npm run M06`

## 01. 让危险操作先回到人这里：工具在执行前请示，没有应答方就必须拒绝

**旁白**

这一集做审批。任务是让危险操作在执行前先回到人这里。命令是 npm run M06，模型会真的决定要不要调那个部署工具。你会看到同一次请求在三种局面下的三个结果：没有应答方是 unavailable，白名单放行是 allowed-once，不在白名单是 rejected。第一种最关键——没人应答时必须拒绝，不能因为忘了配就默认拿到权限。

**本集任务**

让危险操作先回到人这里：工具在执行前请示，没有应答方就必须拒绝

**运行命令**

```bash
cd dsh-example && npm run M06
```

**你将看到**

同一次部署请求在三种应答局面下分别得到 unavailable、allowed-once、rejected

## 02. 三种应答局面的真实结果

**旁白**

三段输出对应三种局面。每段里先是审批决定，然后是工具结果。第一段没有应答方，决定是 unavailable，工具结果 isError 是 true——这就是 fail closed。第二段放行一次，工具真的执行了。第三段被拒绝，模型拿到的是拒绝原因而不是执行结果。注意审批事件是被一轮包住的，这不是巧合：审批的问和答要成对落在日志上，否则重放时是个崩溃尾巴。

**运行命令**

```bash
cd dsh-example && npm run M06
```

**真实输出（节选）**

## 03. 人要求做什么，和系统请求许可，是两个方向

**旁白**

人和系统之间有两个方向，别混在一起。人主动要求，用斜杠命令说，注册表直接接，不消耗模型一轮；系统请求许可，是工具在执行前返回待确认，由应答方决定放这一次还是不放。再往后是结构化提问、计划模式、待办和读取反馈，它们把人参与的状态变成看得见的数据，而不是藏在自然语言里的暗号。数据化的好处很实在：能查、能回放、能做权限。再补一个容易忽略的点：审批的问和答都要落在同一轮里，这样重放的时候这对事件是完整的。如果审批发生在轮外，日志重放到那里就是个断头，审计也就无从谈起。

## 04. 每条请求都必须回，静默丢弃最难查

**旁白**

编排层跑 runner M06 --real。它驱动真实的反向请求，默认策略按选项类型选择拒绝。这里要强调的是：每条请求都必须得到答复。静默丢掉不会安全降级，只会让整轮挂在那儿等超时，而日志上什么都看不见——这类问题最难查。计划模式它没做，因为那归具体内核或宿主。真实模式下你能同时看到：内核在权限策略下作答，编排层的拒绝默认在本地断言成立。顺便给一个自检办法：把应答方摘掉再跑一次，看命令是立刻拒绝还是挂住。立刻拒绝说明 fail closed 写对了，挂住说明有条请求没人回。

**对照命令**

```bash
python -m runtime.runner M06 --real
```

## 05. 整轮挂住不动，日志停在审批那一步

**旁白**

这个症状很典型：命令挂住不动，最后超时，日志里只有审批的问、没有答。定位顺序是先查有没有注册应答方，再查应答方是不是对每个选项都给了明确答复。修法有两半：补上应答方，同时保证没有应答方时立刻拒绝。第二半是关键——挂住比拒绝更糟，因为它把一个策略问题变成了一个可用性问题。

**症状**

命令迟迟不返回，最后超时；日志里有审批的问，没有审批的答。

**定位**

查有没有注册应答方，以及应答方是不是对所有选项都给了明确答复。

**修改**

补上应答方；没有应答方时让请求立刻拒绝，而不是等下去。

## 06. 应答器决定放行还是拒绝，就这几行

**旁白**

代码在哪：M06 的 steps 里那个 approval answerer。它做的判断只有几行：在白名单里就放行一次，否则拒绝。注意「没有应答器」这种情况不在这里处理，是审批服务自己 fail closed —— 这个分工很重要，它保证漏配一个插件不会变成默认放行。你要做按上下文决策的审批，就在这几行里读工具参数，这也是这一集练习要动的地方。

## 07. 把白名单改成按参数判断：只放行非生产环境

**旁白**

练习是把白名单升级成按参数判断。在应答器里读工具参数，环境是生产就拒绝，其余放行一次。跑离线的 M06 验证：参数是 prod 时结果是 rejected，改成 staging 就变成 allowed-once。做完这个练习，你手上就有了一个能按上下文决策的审批点，而不只是一个开关。

**练习**

在应答器里读取工具参数，环境是 prod 时拒绝，其余放行一次。

**验证命令**

```bash
cd dsh-example && npm run M06
```

**可验证答案**

同一个工具在参数为 prod 时得到 rejected，改成 staging 时得到 allowed-once。
