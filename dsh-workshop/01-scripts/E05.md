## 02. 日志不变量与可见面替换

**旁白**

第一处是连续性：序号等于数组下标，中间不许有洞。第二处是冻结：试着改一条事件，拿到的是类型错误而不是改成功。第三处是投影，只有系统、用户、助手、工具这些节点会进去，流式碎片不在其中。第四处是替换，摘要占住被遮区间的原位置，日志长度没变。还有两条 fail-closed 的原文也在屏幕上：区间不在可见面上、引用不完整，都会拒绝而不是静默无效。顺便看一下投影那一行：流式碎片不在里面。这说明「模型看见的」是从事件里折出来的，而不是把所有事件都塞给模型，这也是压缩敢遮的前提。

**运行命令**

```bash
cd dsh-example && npm run M05:real
```

## 03. 分叉只能从闭合的那一轮往下切

**旁白**

有了这两份东西，很多操作才有确定语义。要遮掉旧的一段，就按序号范围换掉可见面，日志一条不动；要分支，只能从已经闭合的那一轮往下切，切在半轮里会被拒绝，因为那样重放出来是个崩溃尾巴；存盘只是存盘，不改变意思。这一集的四个不变量都能一条命令跑出来，你自己写持久化或者审计的时候，先照着它们对一遍，比读文档快。

## 04. 没有序号这件事，写进输出里

**旁白**

编排层跑 runner M05 --real。会话和运行都真的落到存储里，再读回来：消息按用户、助手顺序，运行状态是成功，事件流可查。真实模式下这些事实来自 MiniMax 的真实回答，不是构造的假数据。但它没有那套连号、冻结、换可见面的契约，所以示例干脆把话说明白：当前事件里就是没有序号这个字段。缺什么写进运行输出，比写在文档角落靠得住——你要做严格审计，得先知道这一条。这一集也顺带回答了一个常见疑问：为什么两边编号一样却不能互相替换。因为契约不同——同样叫会话，一边保证连号可回放，一边只保证读写一致。选型时按你需要的保证挑，别按名字挑。

**对照命令**

```bash
python -m runtime.runner M05 --real
```

## 05. 替换可见面时报错，说区间不在可见面上

**旁白**

这个报错第一次遇到很容易误解。它不是说你的序号越界了，而是说你传的是日志下标，而替换要的是可见面上真实存在的节点序号。这两套编号会重合一段，所以偶尔还能跑对，更容易踩。定位办法是先把当前可见面的节点序号打出来，再和你传的值对一遍。改用节点序号就好了。顺带说一句，这种报错比静默无效值钱得多。

**症状**

调用替换时抛错，提示起止序号不在当前可见面的节点里。

**定位**

把当前可见面的节点序号打出来，和你传的起止值对一遍。

**修改**

起止值必须取当前可见面上真实存在的节点序号，而不是事件日志的下标。

## 06. 四条不变量的断言就在这一个文件里

**旁白**

代码在哪：M05 的 phases 里那个 session-log 文件，搜「不变量」就能挨个看到四条断言。它们的写法很值得学：每条都只验证一件事，失败时能立刻定位。你自己给会话层加功能时，先把这四条抄过去当回归测试，改坏了会马上知道。特别是替换区间那条校验，它是把「静默无效」变成「明确报错」的关键。

## 07. 从一个未闭合的轮次里分叉，读出拒绝原因

**旁白**

练习是故意踩一次。把分叉边界改成本轮结束事件之前的某个序号，跑离线的 M05，读一遍拒绝原文。然后改回闭合边界，确认子会话继承的事件数正好等于边界值。这个练习的价值在于：你会记住这个错误长什么样，以后在自己的代码里看到就能立刻定位。

**练习**

把分叉边界改成本轮结束事件之前的一个序号。

**验证命令**

```bash
cd dsh-example && npm run M05
```

**可验证答案**

分叉抛错并说明边界落在未闭合的轮次里；改回闭合边界后子会话继承的事件数与边界值一致。
